# Working on this repo

Everything under `src/` and `.openapi-generator/` is generated by
[openapi-generator](https://openapi-generator.tech)'s `php-nextgen` generator
from `openapi.json`. Don't edit it: the next release overwrites it. Changes to
the API come from the upstream OpenAPI schema. Changes to the *shape* of the
generated code come from `scripts/fix_generated.py`.

Hand-written and safe to edit: `composer.json`, `tests/`, `scripts/`, the
`Makefile`, `.github/`, `README.md`, `phpunit.xml.dist` and this file.
`.openapi-generator-ignore` lists them so the generator leaves them alone.

`api-surface.txt` is written by a tool (`make surface`) and committed. See
[The API surface check](#the-api-surface-check).

## Prerequisites

| Tool | Needed by | Notes |
| --- | --- | --- |
| PHP 8.1 or later, and Composer 2 | `make verify`, `make test`, `make surface` | Or use Docker, below |
| Java 11 or later | `make generate`, `make template-drift` | openapi-generator is a jar; the Makefile downloads it to `/tmp` |
| Python 3 | `make generate` | runs `scripts/fix_generated.py` |
| network | `make fetch`, `make oasdiff`, the first `make verify` | |

Without a local PHP, point the Makefile at Docker:

```sh
make test \
  PHP="docker run --rm -v $PWD:/app -w /app php:8.1-cli php" \
  COMPOSER="docker run --rm -v $PWD:/app -w /app composer:2"
```

`composer.json` sets `config.platform.php` to 8.1, so Composer resolves
development dependencies that run on the floor even when Composer itself runs
on a newer PHP. That setting applies only to this repo, not to consumers.

## Targets

`make help` lists them. The ones that matter:

- `make generate`: clear `src/`, regenerate from the **committed**
  `openapi.json`, then run `scripts/fix_generated.py`. Start here after
  changing anything in `scripts/` or the generator flags.
- `make test`: `composer validate`, load every class, the API surface check,
  then PHPUnit. This is what CI runs.
- `make surface`: rewrite `api-surface.txt` from the current `src/`.
- `make template-drift`: fail if the generator's templates changed under the
  text `scripts/fix_generated.py` matches on.
- `make oasdiff`: the schema gate that stops a release, runnable by hand.

## How a release happens

`.github/workflows/sync.yml`, hourly. When the live schema at
`https://api.incident.io/v1/openapiV3.json` differs from the committed one, it:

1. runs `oasdiff` between the two schemas, and stops if it reports a break;
2. regenerates, and runs `make test` on PHP 8.1 and on the newest PHP;
3. records the new API surface;
4. commits, tags the next **minor** version, and pushes;
5. creates a GitHub release;
6. waits until Packagist lists the new version.

There is no publish step. Packagist reads versions from git tags, and its
GitHub webhook tells it about each push, including pushes made with
`GITHUB_TOKEN`. Nothing writes a version into `composer.json`: Packagist takes
the version from the tag.

A human is needed only when a gate trips, and each trip files an issue:

- **`breaking-change`**: oasdiff found a break. The new schema is **not**
  committed, so every later run sees the same diff and halts the same way until
  someone acts. The issue is deduped for that reason.
- **`release-stuck`**: something failed after the schema changed. The issue
  says which of three cases it is (failed before committing, tagged with no
  GitHub release, or tagged but not on Packagist) and what to do.

To release a breaking change, run the workflow from the Actions tab with
**bump: major** and **acknowledge_breaking: true**. Both are required together.
An acknowledged major also rewrites `api-surface.txt` before checking it, since
the removals are what is being released.

Patch versions are never cut automatically. They are for hand fixes to
`scripts/` or `composer.json`: commit, then tag and push `vX.Y.Z+1` yourself.

## Why the generated code is shaped the way it is

The API's compatibility policy treats adding an endpoint, a response property,
an optional request parameter or an enum value as backwards-compatible, and
those release without a human. `scripts/fix_generated.py` changes the generated
code where it would otherwise break on one of them, or where it is wrong:

- **Open enums.** The generated setters throw `InvalidArgumentException` on an
  enum value not in the schema, and deserialization goes through the setters,
  so every installed client would fail on the first response carrying a new
  value. The checks are removed; the constants and `get*AllowableValues()` stay.
  The generator's own `enumUnknownDefaultCase` option is not used, because it
  replaces an unknown value with the string `unknown_default_open_api`, which
  loses the value on responses and sends that string to the API on requests.
- **Filter parameters.** The API's filters are object-typed query parameters,
  decoded as `status[one_of]=a&status[one_of]=b`. With `form` style the
  generator encodes them as `0=a&1=b`, dropping the parameter name, so the
  server ignores the filter. With `deepObject` it sends
  `status[one_of][0]=a&status[one_of][1]=b`, of which the server keeps one
  value. `ObjectSerializer::toQueryValue` is patched to send the repeated-key
  form for both styles, at any nesting depth
  (`custom_field[<id>][one_of]=<value>`).
- **User agent.** `incident-io-sdk-php/<version>`, matching sdk-go and
  sdk-rust. The version comes from `Composer\InstalledVersions` at runtime,
  since the tag is the only place it exists.
- **File headers.** The generator pastes the schema's whole introduction
  (about 9KB) into the docblock of every file, about a third of the package's
  size. It is removed.

It also asserts that every deprecated operation carries `@deprecated`, which the
generator emits itself.

Every rewrite fails the run if it matches nothing, or fewer times than the
schema says it should, and prints `not safe to publish`. That turns a generator
change into a stopped release instead of a patch that silently stopped
applying. The rewrites anchor on generated text rather than forking the
templates, because openapi-generator runs mustache without fail-on-missing-key:
a forked template whose variable was renamed upstream drops a branch without
any error. `templates/pristine/` holds unmodified upstream copies of the five
templates the rewrites depend on, used only by `make template-drift`.

### The API surface check

oasdiff compares the wire contract. Several changes it rates as compatible
still break PHP callers: renaming a component schema renames a model class, a
changed operationId or tag renames a method or Api class, and a renamed path
parameter renames a named argument. oasdiff also doesn't see schemas that no
path references, such as the audit log and webhook payloads, so removing a
property from one of those removes a getter without oasdiff noticing.

`scripts/verify.php` loads every class, then records one line per class,
constant, model property, method and method parameter name in
`api-surface.txt`. `make verify` fails if any recorded line has disappeared.
Additions are allowed, and the release records them after a passing check, so
something added in one release and removed in the next is caught.

Parameters are recorded by name, not position. The API inserts new optional
parameters among existing ones, which moves the later ones and breaks
positional calls but not named ones. The README tells callers to use named
arguments, and that is the contract checked here.

Replayed against sdk-go's 124 committed schema changes, oasdiff would have
halted 3 releases and the surface check 4 more, all for genuine removals.
Recording parameter positions would have halted another 7.

Loading every class through Composer's autoloader is also the nearest thing PHP
has to a compile. `php -l` parses one file at a time and does not notice a class
extending something missing or a namespace that disagrees with its path.
Loading parses every file too, so there is no separate `php -l` pass.

## First release checklist

The package does not exist on Packagist yet, and the hourly loop is switched
off until it does. In order:

1. **Create `incident-io/sdk-php` on GitHub** as a public repository, and push
   `master`. Leave `master` unprotected: the release job pushes to it directly
   with `GITHUB_TOKEN`.
2. **Tag the first version by hand.** The committed schema is the live one, so
   the workflow would find nothing to release.
   `git tag v1.0.0 && git push origin v1.0.0 && gh release create v1.0.0 --generate-notes`.
3. **Register the package on Packagist**: sign in with the incident.io
   Packagist account, submit `https://github.com/incident-io/sdk-php`, and
   confirm the package page shows no warning about the GitHub hook. Packagist
   reads the `v1.0.0` tag on its first crawl.
4. **Run the workflow once manually** with `dry_run: true` and confirm it
   reports "Schema unchanged" or, if the schema has moved since, a version.
5. **Uncomment the `schedule:` block** at the top of
   `.github/workflows/sync.yml`. Nothing else enables the loop, and nothing
   checks that you did.

## Keeping the loop alive

Everything that reports a problem here is a `failure()` hook, and a loop that
never runs never fails. Two ways it can go quiet:

- GitHub **disables a scheduled workflow after 60 days** with no repository
  activity, and emails only whoever last edited the cron. This repo's activity
  is its own release commits, which stop when the schema stops changing.
- Someone reverts or never enables the cron.

Each run writes a line to its job summary saying what it decided, so "when did
this last sync?" is answerable from the Actions run list. If the run list is
empty for a week, the loop is off, not quiet.

## Upgrading openapi-generator

`OPENAPI_GENERATOR_VERSION` in the `Makefile` is pinned deliberately. The
project ships no patch releases, so every available upgrade is a minor, which
its own policy says may change template variables. `php-nextgen` is also
marked beta upstream.

1. Change the version and run `make template-drift`. It will fail and print the
   diff against `templates/pristine/`.
2. Read the diff. Decide whether each rewrite in `scripts/fix_generated.py`
   still applies.
3. Copy the new templates over `templates/pristine/`, run `make generate`, and
   check the counts it prints did not collapse.
4. `make test`. If the surface check reports removals, the upgrade renamed
   something callers use, and it needs a major release.
